# Installation — Windows workstation without Internet access

This guide is intended for a current 64-bit Windows workstation that **cannot access the Internet**.

The target workstation does **not** need to have Python, Conda, or Miniforge installed. Instead, you will prepare a complete TotalSegmentator Conda environment on a second Windows computer that has Internet access, pack that environment, and transfer it to the offline workstation.

You must also transfer the **TotalSegmentator model weights**. The model weights are stored separately from the Conda environment and are not automatically included by `conda-pack`.

> **You need two computers**
>
> 1. **Preparation PC:** Windows PC with Internet access.
> 2. **Target PC:** the offline workstation where GUI for TotalSegmentator will run.
>
> Use a preparation PC with the same general platform as the target: **64-bit Windows → 64-bit Windows**. `conda-pack` environments are platform-specific.

Last checked against the upstream documentation: **September 2026**.

---

# Part A — Check the target workstation first

Before building the environment, collect a few details from the offline workstation.

## 1. Confirm that Windows is 64-bit

1. Press **Windows + I**.
2. Open **System → About**.
3. Find **System type**.

It should say something similar to:

```text
64-bit operating system, x64-based processor
```

---

## 2. Check the NVIDIA GPU and driver

If you plan to use GPU acceleration, on the **Target PC:**:

1. Press **Windows + R**.
2. Type:

   ```text
   cmd
   ```

3. Press **Enter**.
4. Run:

   ```bat
   nvidia-smi
   ```

Write down:

- the GPU model;
- **Driver Version**;
- the CUDA version displayed by `nvidia-smi`.

You will use this information when choosing the PyTorch package on the Internet-connected preparation PC.

If `nvidia-smi` is not available, you can prepare a CPU-only environment instead. TotalSegmentator can run on CPU, but it can be much slower.

---

# Part B — Prepare everything on the Internet-connected PC

## 3. Download GUI for TotalSegmentator

Open:

[GUI for TotalSegmentator](https://github.com/EugeneHoldman/GUI-for-TotalSegmentator)

Then open:

[Project releases](https://github.com/EugeneHoldman/GUI-for-TotalSegmentator/releases)

Download:

- the latest Windows GUI distribution;
- the **Conda environment path patch** supplied by this project.

The commands later in this guide refer to the patch as:

```text
fix_conda_env_paths.py
```

If the actual file in the release has a different name, use that exact filename instead.

Do not run the GUI yet. Keep these files for transfer to the offline workstation.

---

## 4. Install Miniforge on the preparation PC

Download Miniforge from:

[Miniforge](https://github.com/conda-forge/miniforge)

Choose the current Windows x86_64 installer, normally named similarly to:

```text
Miniforge3-Windows-x86_64.exe
```

Run it and keep the **Start-menu shortcut** option enabled.

You normally do not need to add Miniforge to the system PATH. Use **Miniforge Prompt** instead.

If possible, install Miniforge in a short path containing only ordinary Latin characters, for example:

```text
C:\Miniforge3
```

---

## 5. Open Miniforge Prompt

1. Press the **Windows key**.
2. Type:

   ```text
   Miniforge Prompt
   ```

3. Open it.

All commands in the preparation section should be entered into this window.

---

## 6. Create the environment

Run:

```bat
conda create -n totalseg_offline python=3.11 pip -y
```

Activate it:

```bat
conda activate totalseg_offline
```

Upgrade `pip`:

```bat
python -m pip install --upgrade pip
```

---

## 7. Install PyTorch for the TARGET workstation

The PyTorch build must be selected for the **offline target PC**, not for the preparation PC.

Open:

[PyTorch — Start Locally](https://pytorch.org/get-started/locally/)

Select:

- **OS:** Windows
- **Package:** Pip
- **Language:** Python
- **Compute platform:** a CUDA build supported by the target workstation's NVIDIA driver, or CPU

Copy the command generated by PyTorch and run it in the activated `(totalseg_offline)` Miniforge Prompt.

Example of a CUDA installation command:

```bat
python -m pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu118
```

Example of a CPU installation command:

```bat
python -m pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cpu
```

These are examples only. Use the command appropriate for the target workstation.

Older releases can be found here:

[PyTorch — Previous Versions](https://pytorch.org/get-started/previous-versions/)

Verify PyTorch:

```bat
python -c "import torch; print('PyTorch:', torch.__version__); print('CUDA runtime:', torch.version.cuda); print('GPU visible on preparation PC:', torch.cuda.is_available())"
```

It is acceptable for `GPU visible on preparation PC` to be `False` if the preparation PC itself does not contain a suitable NVIDIA GPU. What matters is that you installed the PyTorch build intended for the **target** workstation.

---

## 8. Install TotalSegmentator

Run:

```bat
python -m pip install TotalSegmentator
```

Verify:

```bat
TotalSegmentator --version
```

Then run:

```bat
python -m pip check
```

Upstream documentation:

[TotalSegmentator](https://github.com/wasserth/TotalSegmentator)

---

## 9. Configure the TotalSegmentator license before going offline

If you use only open TotalSegmentator tasks, skip this section.

If you need licensed tasks, obtain the license from the TotalSegmentator authors while you still have Internet access.

See:

[TotalSegmentator tasks and licensing](https://github.com/wasserth/TotalSegmentator#subtasks)

Then run:

```bat
totalseg_set_license -l YOUR_LICENSE_NUMBER
```

Example:

```bat
totalseg_set_license -l aca_12345678910
```

The example above is not a real license.

It is important to configure the license on the Internet-connected preparation PC because the initial license validation requires network access.

---

## 10. Download the TotalSegmentator model weights

This step is **essential** for an offline workstation.

The TotalSegmentator Python package is inside the Conda environment, but the model weights are **not** stored inside that environment by default. They must be downloaded separately while the preparation PC still has Internet access.

Make sure the environment is active:

```bat
conda activate totalseg_offline
```

The beginning of the Miniforge Prompt should contain:

```text
(totalseg_offline)
```

### Option A — download only the tasks you need

Run:

```bat
totalseg_download_weights -t TASK_NAME
```

For example:

```bat
totalseg_download_weights -t total
```

Repeat the command for every TotalSegmentator task that must work on the offline PC.

To list tasks available in the installed TotalSegmentator version:

```bat
TotalSegmentator --list-tasks
```

### Option B — download all available model weights

Current TotalSegmentator versions also provide:

```bat
totalseg_download_weights -t all
```

This requests all downloadable model weights known to the installed TotalSegmentator version.

This is convenient if you want the offline installation to be as self-contained as possible, but keep in mind that:

- the download can be very large;
- it includes models that this CT-only GUI may not use, including non-CT tasks;
- licensed models require a valid TotalSegmentator license to be configured first.

If you plan to use licensed tasks, run `totalseg_set_license` before downloading those weights.

### Where do the downloaded weights go?

Even though `totalseg_download_weights` is being run from the activated **Conda/Miniforge Prompt**, the weights do **not** go into:

```text
C:\Miniforge3\envs\totalseg_offline
```

By default they go into the **Windows user profile** of the account that runs the command:

```text
%USERPROFILE%\.totalsegmentator\nnunet\results
```

For example:

```text
C:\Users\John\.totalsegmentator\nnunet\results
```

The broader TotalSegmentator configuration folder is:

```text
%USERPROFILE%\.totalsegmentator
```

You can display the current Windows user-profile path with:

```bat
echo %USERPROFILE%
```

After downloading the models, confirm that the folder exists:

```bat
dir "%USERPROFILE%\.totalsegmentator\nnunet\results"
```

### Why this folder is separate from Conda

Activating the Conda environment only selects the Python installation and the `totalseg_download_weights` program that will run.

TotalSegmentator itself chooses the model-storage location. Its default is the user's `.totalsegmentator` folder, independently of where Python or Conda is installed.

Therefore the offline transfer has **two separate parts**:

1. the packed Conda environment;
2. the `.totalsegmentator` folder containing weights and configuration.

Copy the entire:

```text
%USERPROFILE%\.totalsegmentator
```

folder to the offline PC as described later in this guide.

The current TotalSegmentator source for the download command includes an `all` option:

[TotalSegmentator — `totalseg_download_weights.py`](https://github.com/wasserth/TotalSegmentator/blob/master/totalsegmentator/bin/totalseg_download_weights.py)

Upstream offline guidance:

[TotalSegmentator](https://github.com/wasserth/TotalSegmentator)

### Optional: use a custom weights folder

GUI for TotalSegmentator supports a custom TotalSegmentator weights path.

Advanced users can therefore keep the weights in a dedicated folder rather than in the default user profile. This can make transfer between workstations more explicit.

For the simplest installation, however, this guide uses the **default `.totalsegmentator` location**, because it matches the upstream TotalSegmentator behavior and requires fewer settings.

## 11. Install conda-pack

`conda-pack` creates a relocatable archive of the Conda environment.

Official documentation:

[conda-pack](https://conda.github.io/conda-pack/)

Deactivate the TotalSegmentator environment:

```bat
conda deactivate
```

Install `conda-pack` into the base Miniforge environment:

```bat
conda install -n base -c conda-forge conda-pack -y
```

---

## 12. Pack the environment

Run:

```bat
conda pack -n totalseg_offline -o "%USERPROFILE%\Downloads\TotalSegmentator_env.zip" --format zip
```

When the command finishes, you should have:

```text
TotalSegmentator_env.zip
```

in your Windows **Downloads** folder.

Do not manually copy the original `C:\Miniforge3\envs\totalseg_offline` folder. Use the archive produced by `conda-pack`.

`conda-pack` exists specifically because ordinary Conda environments contain installation-path references and cannot safely be relocated by simply copying the folder.

---

## 13. Prepare the transfer package

Copy the following to an approved USB drive, external drive, or other transfer medium:

1. the GUI for TotalSegmentator Windows distribution;
2. `TotalSegmentator_env.zip`;
3. the project's Conda environment path-patch script;
4. the complete:

   ```text
   %USERPROFILE%\.totalsegmentator
   ```

   folder;
5. this installation guide.

### How to find `.totalsegmentator`

1. Open **File Explorer**.
2. Click the address bar.
3. Paste:

   ```text
   %USERPROFILE%\.totalsegmentator
   ```

4. Press **Enter**.
5. Copy the entire folder.

If the folder does not exist, TotalSegmentator has not yet created its configuration/downloaded model files.

---

# Part C — Install on the offline target workstation

## 14. Create permanent folders

Use a short installation path.

For example:

```text
C:\TotalSeg
```

Inside it, create:

```text
C:\TotalSeg\GUI
C:\TotalSeg\env
```

Avoid very deep directory structures, spaces, and non-standard characters where possible. This reduces the chance of Windows path-length and prefix-replacement problems.

If hospital policy does not allow writing to `C:\TotalSeg`, use another permanent location approved by your IT department.

---

## 15. Extract the GUI

Extract the GUI distribution into:

```text
C:\TotalSeg\GUI
```

Do not run it directly from the ZIP archive.

---

## 16. Extract the Conda environment

Extract:

```text
TotalSegmentator_env.zip
```

into:

```text
C:\TotalSeg\env
```

After extraction, check that this file exists:

```text
C:\TotalSeg\env\python.exe
```

and that these folders exist:

```text
C:\TotalSeg\env\Lib
C:\TotalSeg\env\Scripts
```

If you instead see something such as:

```text
C:\TotalSeg\env\TotalSegmentator_env\python.exe
```

you created an unnecessary extra folder level. Move the **contents** so that `python.exe` is directly inside `C:\TotalSeg\env` before continuing.

---

## 17. Copy the TotalSegmentator weights and configuration

On the target PC:

1. Open **File Explorer**.
2. Click the address bar.
3. Enter:

   ```text
   %USERPROFILE%
   ```

4. Press **Enter**.
5. Copy the transferred `.totalsegmentator` folder into this location.

The final path should be:

```text
%USERPROFILE%\.totalsegmentator
```

This carries the model weights and TotalSegmentator configuration prepared on the Internet-connected PC.

---

## 18. Copy the custom environment path patch

Copy the project's Conda environment path-patch script into:

```text
C:\TotalSeg\env\Lib
```

This guide assumes the filename:

```text
fix_conda_env_paths.py
```

The resulting path should therefore be:

```text
C:\TotalSeg\env\Lib\fix_conda_env_paths.py
```

If the project uses another filename, substitute that filename in the command below.

---

## 19. Run conda-unpack

`conda-unpack` replaces many path references that still point to the preparation PC.

### Open Command Prompt

1. Press **Windows + R**.
2. Type:

   ```text
   cmd
   ```

3. Press **Enter**.

Run:

```bat
cd /d C:\TotalSeg\env
```

Activate the packed environment:

```bat
call Scripts\activate.bat
```

Then run:

```bat
Scripts\conda-unpack.exe
```

Wait until the command completes.

---

## 20. Run the project's additional path patch

The project-specific patch is used because some paths in this Windows environment may remain tied to the original build location even after the standard `conda-unpack` step.

With the environment still activated, run:

```bat
python Lib\fix_conda_env_paths.py
```

If your downloaded patch has a different filename, use that exact name.

> **Important**
>
> Once `conda-unpack` and the custom path patch have been run, do not move or rename `C:\TotalSeg\env`.
>
> If the environment must be installed somewhere else later, delete it, extract a fresh copy of `TotalSegmentator_env.zip` into the final location, and run both repair steps again.

---

## 21. Verify the offline environment

In the same Command Prompt, run:

```bat
where python
```

The first result should point to:

```text
C:\TotalSeg\env\python.exe
```

Check Python:

```bat
python --version
```

Check TotalSegmentator:

```bat
TotalSegmentator --version
```

Check PyTorch:

```bat
python -c "import torch; print('PyTorch:', torch.__version__); print('CUDA runtime:', torch.version.cuda); print('GPU available:', torch.cuda.is_available())"
```

Check package consistency:

```bat
python -m pip check
```

If the target has a compatible NVIDIA GPU, `GPU available` should be:

```text
True
```

# Troubleshooting

## TotalSegmentator tries to download a model

The corresponding task weights are missing.

On the preparation PC:

```bat
conda activate totalseg_offline
```

Then:

```bat
totalseg_download_weights -t TASK_NAME
```

Copy the updated `.totalsegmentator` folder to the target.

---

## A licensed task fails offline

Confirm that, on the Internet-connected preparation PC:

1. the license was configured successfully;
2. the licensed task's model was downloaded successfully;
3. the full `.totalsegmentator` folder was copied to the target.

Do not rely on the offline workstation to perform the initial license/model download.

---

## `GPU available: False`

Possible causes include:

- CPU-only PyTorch was packed;
- the target NVIDIA driver is missing;
- the PyTorch CUDA build is not compatible with the target driver.

Rebuild the environment on the preparation PC with the correct PyTorch package.

---

## `DLL load failed` or a missing Microsoft runtime DLL

Some Windows Python packages require the Microsoft Visual C++ runtime.

Use Microsoft's official documentation:

[Latest supported Visual C++ Redistributable downloads](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist)

For a 64-bit Windows workstation, use the x64 package unless your local IT policy specifies otherwise.

Download the installer on the Internet-connected PC and transfer it to the offline workstation. Do not download runtime DLL files individually from third-party websites.

---

## Very long path / extraction errors

Keep the environment in a short path such as:

```text
C:\TotalSeg\env
```

`conda-pack` also recommends enabling Windows long-path support when appropriate. On a managed workstation, ask IT to make that change rather than modifying system policy yourself.

Microsoft documentation:

[Maximum Path Length Limitation](https://learn.microsoft.com/en-us/windows/win32/fileio/maximum-file-path-limitation)
